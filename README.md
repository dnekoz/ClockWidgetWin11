# External IP Widget

Работающее приложение для Windows 10/11: компактный виджет внешнего IPv4, приблизительная геолокация и постоянный значок в трее. Интерфейс на русском языке. Нет телеметрии, рекламы, GPS, платных API и обязательных ключей.

## Запуск готового приложения

Запустите `artifacts/win-x64-portable/ExternalIpWidget.exe`. Это автономная x64-сборка с .NET внутри; установка среды выполнения и права администратора не нужны. Для переноса достаточно exe. Автозапуск и «Поверх всех окон» изначально выключены.

**Ограничение данной рабочей среды:** её политика контроля приложений блокирует запуск собранного exe. Сборка не подписана сертификатом издателя. Политика не изменялась. Интерфейс и сетевые операции проверены стандартным запуском DLL через установленный .NET. Для такого запуска предоставлена дополнительная папка `artifacts/dotnet-desktop` и скрипт `run.ps1`:

```powershell
.\run.ps1
.\run.ps1 -Settings
# Или при наличии .NET 10 Desktop Runtime в PATH:
dotnet artifacts/dotnet-desktop/ExternalIpWidget.dll --settings
```

В сборке DLL требуется установленный .NET 10 **Desktop** Runtime либо SDK. Скрипт также находит SDK, установленный в рабочей среде задачи. Запуск на другой машине с политикой запрета неподписанного кода зависит от правил этой машины; не отключайте защиту ради приложения.

- Перетащите виджет за заголовок, IP или расположение. Положение сохраняется после перемещения.
- «Копировать» копирует только IPv4; двойной щелчок по IP также копирует адрес.
- Кнопка «—» скрывает виджет, шестерёнка открывает настройки.
- Правый щелчок по значку трея: показать/скрыть, копировать IP, обновить, настройки, выход.
- Двойной щелчок по значку трея показывает виджет. Повторный запуск exe активирует уже запущенный экземпляр и показывает его виджет.
- Аргумент `--settings` открывает настройки, в том числе у уже запущенного экземпляра.
- Закрытие настроек оставляет приложение работающим. Полное завершение — пункт «Выход».

Архив `artifacts/ExternalIpWidget-win-x64.zip` содержит exe и инструкции; `artifacts/ExternalIpWidget-dotnet.zip` — сборку DLL и скрипт запуска; `artifacts/ExternalIpWidget-source.zip` — исходный код и тесты без промежуточных файлов сборки.

## Стек и совместимость

C# / .NET 10 LTS / Windows Forms. Нативные окна, NotifyIcon, асинхронный HttpClient и отсутствие WebView уменьшают накладные расходы. Сетевой клиент переиспользуется; при простое нет анимации и частого опроса. Компоненты не требуют сторонних NuGet-пакетов. .NET 10 имеет [долгосрочную поддержку](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).

Целевая платформа — Windows 10/11, x64; скрипт также позволяет собрать x86 и ARM64. Таблица официальной поддержки .NET зависит от редакции и срока поддержки Windows: Microsoft отдельно указывает Windows 10 LTSC/Enterprise в [списке поддерживаемых Windows](https://learn.microsoft.com/en-us/dotnet/core/install/windows). Наличие работающего приложения не продлевает поддержку ОС. Фактические проверки этой сборки приведены в [VERIFICATION.md](VERIFICATION.md).

## Сборка и тесты

Установите [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0), затем из каталога проекта:

Перед повторной сборкой завершите работающий экземпляр через пункт «Выход» в трее, чтобы Windows освободила DLL и exe.

```powershell
dotnet build ExternalIpWidget.slnx -c Release
dotnet run --project tests/ExternalIp.Tests -c Release
dotnet run --project src/ExternalIp.Widget -c Release
```

Тесты — самостоятельный консольный runner без внешних пакетов: код возврата 0 означает успех, 1 — ошибку. Используется `dotnet run`, а не `dotnet test`. Изолированные временные файлы автоматически удаляются. Два транспортных теста используют локальные IPv4-сокеты без изменения доверенных сертификатов компьютера.

Проверка реальных сервисов (дополнительно пять сетевых тестов):

```powershell
dotnet run --project tests/ExternalIp.Tests -c Release -- --live
```

Получение автономного exe:

```powershell
.\build.ps1
# Другие архитектуры:
.\build.ps1 -Runtime win-arm64
# Небольшой exe для машины с установленным .NET 10 Desktop Runtime:
.\build.ps1 -FrameworkDependent
```

`build.ps1` сначала собирает решение и запускает тесты, затем публикует приложение. Параметр `-SkipTests` пропускает тесты. Если dotnet отсутствует в PATH, скрипт также проверяет SDK в `%LOCALAPPDATA%\ExternalIpWidget.Build\dotnet` — именно туда SDK установлен в рабочей среде этой задачи. Скрипт отключает телеметрию CLI; приложение её не содержит. Точный эквивалент публикации:

```powershell
dotnet publish src/ExternalIp.Widget -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o artifacts/win-x64-portable
```

Единственный exe большой, потому что включает .NET Desktop Runtime. При запуске нативные библиотеки извлекаются штатным механизмом .NET в пользовательский временный кэш. При переносе exe с включённым автозапуском откройте настройки и выключите/включите автозапуск, чтобы обновить путь.

## Настройки и поведение

Изменения применяются кнопкой «Применить» или «Сохранить и закрыть» без перезапуска. «Закрыть» отбрасывает ещё не применённые изменения.

| Параметр | По умолчанию | Допустимые значения |
|---|---|---|
| Автообновление | 60 секунд | 10–86400 секунд |
| Тайм-аут всего запроса (DNS, TCP, TLS, тело) | 5 секунд | 1–60 секунд |
| Геолокация | Включена | Вкл./выкл. |
| Виджет | Видим | Показать/скрыть |
| Поверх всех окон | Выключено | Вкл./выкл. |
| Автозапуск | Выключен | Текущий пользователь, HKCU Run |

Каждый список сервисов поддерживает добавление, редактирование, удаление, включение/отключение, перемещение вверх/вниз и проверку выбранного сервиса. Сервисы опрашиваются строго по списку до первого корректного ответа. Одновременно выполняется максимум один цикл обновления. Повторные команды во время цикла объединяются; изменение настроек отменяет старый цикл. Смена сетевых адресов вызывает обновление с задержкой 2 секунды.

Пути JSON: `data.ip`, `items.0.ip`, `$.data.ip`, JSON Pointer `/data/ip`; экранирование Pointer `~0` и `~1` поддерживается. Для IP-сервиса можно выбрать обычный текст или JSON. Для геосервиса обязательно указывается `{ip}` в URL, а поля страны, региона и города настраиваются независимо. Ненужные поля оставьте пустыми. Поле IP в геоответе необязательно; если указано, ответ принимается только при совпадении с запрошенным IP. Необязательное поле успешности должно быть JSON-значением `true`.

Показываются только заполненные страна/регион/город, без повторов (без учёта регистра). Названия передаются так, как их вернул сервис, обычно на английском. При недоступной геолокации остаются IP и «Местоположение не определено». Когда меняется IP, старая геолокация удаляется **до** нового геозапроса. Для того же IP ошибка геосервиса сохраняет последнее расположение с отметкой «устарело». При штатной паузе API допускается последний успешный кэш того же IP; время геоданных видно в подсказке расположения.

Если IP не получен, показывается «IP недоступен»; если он уже был определён — последний адрес и «Данные устарели». Последние данные сохраняются между запусками и до нового успешного запроса явно считаются устаревшими. Время «Обновлено» — время последнего успешного получения **IP** в часовом поясе Windows.

Файлы в `%LOCALAPPDATA%\ExternalIpWidget`:

- `settings.json` — настройки, порядок сервисов и координаты виджета;
- `last-data.json` — последний IP, геолокация и время успеха;
- `api-usage.json` — минимальные паузы, счётчики последних 24 часов, задержки после ошибок;
- `.bak` — предыдущая версия соответствующего файла.

Запись через временный файл с заменой; повреждённые настройки восстанавливаются из проверенной резервной копии, иначе используются значения по умолчанию с сообщением в диагностике. Счётчики API переживают перезапуск. Ошибки записи не завершают приложение и видны на вкладке «Диагностика».

## Сервисы, проверенные 30 октября 2026

До реализации выполнены прямые `curl -4 --noproxy '*'` запросы с проверкой TLS: все пять URL вернули HTTP 200. После реализации те же форматы проверены транспортом самого приложения; отчёт — в VERIFICATION.md. Это проверка доступности из данной сети, не гарантия доступности из любой страны/сети.

| Назначение / сервис | URL | Разбор / ограничения |
|---|---|---|
| IP: ipify | `https://api.ipify.org?format=json` | JSON `ip`. [Документация](https://www.ipify.org/) разрешает использование без лимита. |
| IP: icanhazip / Cloudflare | `https://ipv4.icanhazip.com` | Текст. [Сведения владельца](https://major.io/icanhazip-com-faq/). Числовой лимит в найденных официальных материалах не указан; не предполагается безлимитность. Локальная пауза ≥10 с. |
| IP: Amazon CheckIP | `https://checkip.amazonaws.com` | Текст. [Пример использования AWS](https://docs.aws.amazon.com/cli/latest/userguide/bash_cloudformation_code_examples.html). Публичная числовая квота не найдена; локальная пауза ≥10 с, без SLA. |
| Геолокация: GeoJS | `https://get.geojs.io/v1/ip/geo/{ip}.json` | JSON `country`, `region`, `city`, `ip`. [Формат](https://www.geojs.io/docs/v1/endpoints/geo/), [текущие лимиты](https://www.geojs.io/docs/general/): не заявлены; [условия](https://www.geojs.io/tos/) допускают ограничение избыточного использования. В приложении пауза ≥60 с. |
| Геолокация: ipwho.is | `https://ipwho.is/{ip}` | JSON `country`, `region`, `city`, `ip`, `success`. [Документация](https://ipwhois.io/documentation): HTTPS, без ключа, 1000 запросов в сутки на IP, разрешено коммерческое использование, без SLA. В приложении ≤900 за скользящие 24 ч и пауза ≥120 с. |

Для встроенных доменов геосервисов нижние границы пауз/квот нельзя ослабить даже редактированием настроек. Для пользовательских сервисов задаются минимальная пауза и суточный лимит; 0 означает отсутствие локальной суточной квоты. Счётчики общие для домена, включая тестовые и ручные запросы. HTTP 429 учитывает `Retry-After` (секунды или дату); при отсутствии заголовка выдерживается 24 часа. Другие ошибки увеличивают паузу экспоненциально до 15 минут. Никаких внутренних бесконечных повторов нет. Внешние запросы других приложений за тем же NAT в локальные счётчики не входят; окончательное ограничение остаётся у сервиса.

## Принятые допущения и ограничения

- Определяется **адрес выхода конкретного запроса**, а не все адреса интерфейсов. VPN и NAT учитываются маршрутизацией Windows. Чтобы гарантировать IPv4 TCP, приложение использует A-записи и IPv4-сокеты, HTTP/1.1 и прямое соединение, без системного HTTP-прокси. Если сеть разрешает интернет только через прокси, сервисы могут быть недоступны. Геолокация всё равно запрашивается именно для уже найденного IP, даже если маршрут изменился.
- Проверяются HTTPS, штатная цепочка сертификатов Windows и имя сервера; обхода проверки нет. Перенаправления отключены, поэтому задавайте конечный HTTPS URL. Ответы ограничены 64 КиБ, глубина JSON — 32.
- При отключении геолокации её сервисы не вызываются, кэш расположения убирается из интерфейса. В настройках отключённую геолокацию нельзя проверить, пока её не включат.
- Минимальные паузы API имеют приоритет над частотой автообновления. При обновлении каждые 10 с геосервисы не будут опрашиваться каждые 10 с.
- Значок постоянно зарегистрирован, но Windows может поместить его в меню скрытых значков. Нативная подсказка трея ограничена 127 символами; длинное расположение сокращается многоточием. Полное расположение доступно в подсказке виджета.
- Виджет использует Per-Monitor V2 DPI и возвращается в рабочую область доступного монитора, если экран отключён. Для смены DPI нужен Windows 10 1703+; ориентир сборки — современные Windows 10/11.
- Допускается один экземпляр на пользователя и сеанс Windows, включая запуски с разными профилями. Технический параметр `--profile <каталог>` выбирает хранилище для изолированного тестирования при запуске первого экземпляра. Повторный запуск показывает существующий. Автозапуск предназначен для стандартного профиля.
- Физическое расположение компьютера, точность до дома и русификация геобаз не предполагаются. Источники могут расходиться; используется первый успешный по порядку пользователя.

## Код и ручная проверка

`src/ExternalIp.Core` содержит проверку IPv4, разбор ответов, хранилища, IPv4 HTTPS-транспорт, лимитер, переключение сервисов и машину состояния обновлений. `IIpLookup`, `IGeoLookup`, `IHttpTransport`, `TimeProvider` позволяют тестировать их независимо от окон. `src/ExternalIp.Widget` содержит WinForms-виджет, настройки, трей, HKCU-автозапуск и Windows-события. `tests/ExternalIp.Tests` содержит воспроизводимые тесты.

Чек-лист проверки интерфейса и отдельно невыполненные проверки находятся в [VERIFICATION.md](VERIFICATION.md).
